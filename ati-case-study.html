The Problem

The Impact of This Project

Fragmented Tools

Agents juggled spreadsheets, phone logs, and manual clinic coordination no single source of truth.

Slow Discovery

Finding slots across 900+ clinics was manual. No way to compare options or filter by preference.

Missing Patient Data

Information scattered across systems. No consolidated profile with history, documents, preferences.

Double Booking Risk

No real time slot visibility. Agents couldn't verify if a slot was already taken before confirming.

Lack of Automated Reminders

Manual phone calls for confirmations and reminders. High rate of missed appointments.

Research & Discovery

How We Uncovered the Real Problems

Before designing any screens, I invested time understanding the existing workflow through direct observation and stakeholder conversations. This shaped every design decision that followed.

Agent Interviews

Conducted sessions with scheduling agents to understand how they currently coordinate appointments across 900+ clinics. Agents described switching between 4-5 tools per booking.

"I have to copy patient info from one screen, open a spreadsheet, call the clinic, then log everything again."

Workflow Shadowing

Observed agents during live scheduling calls to identify friction points in real time. Documented the exact sequence of tools and manual steps they used.

"Sometimes I book a slot, and 10 minutes later find out someone else already took it."

Stakeholder Alignment

Worked with product and engineering to map system constraints, data sources, and API capabilities. Documented 9 critical questions that shaped the v1 scope.

"We need to know what data the system can surface in real-time vs what requires a manual lookup."

Key Insight:The core problem wasn't "agents need a new tool" it was "agents can't see availability and patient data in same place." This reframed the entire product around a unified scheduling view.

Design Exploration

How I Arrived at the Final Design

The final UI was the result of multiple exploration cycles. Here are the key decisions that shaped the Appointment Scheduler the core screen of the platform.

Card View vs Table View

  • Table View: Dense grid with sortable columns. Fast for comparing 20+ slots at once, but agents lost patient context.
  • Card View: Clinics grouped with slots nested inside. Distance and ratings visible at a glance. Agents can browse naturally.
  • Why: Card view tested better in agent feedback sessions. Table view retained as an option for power users who prefer density.

Filter Placement: Top Bar vs Side Panel

  • Top Bar: Horizontal filter row above results. Compact, filters were cramped with 6+ criteria. No room for patient details.
  • Left Side Panel: Vertical filter stack with patient details below. Agents see filters AND patient context simultaneously.
  • Why: During shadowing, agents constantly referenced patient info while filtering. Co-locating them eliminated tab-switching.

Map: Full Page vs Detail Dialog

  • Agents had to leave scheduling and navigate back to book.
  • "View on Map" Dialog: Inline modal with travel info, ratings, hours, and Call Clinic CTA. Agent stays in the scheduler.
  • Why: V1 scope required minimal flow disruption. Full-page map planned for v2 with heatmap and direct booking from pins.
